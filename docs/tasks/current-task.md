# Task: ขอบของรูปที่วาดด้วย `fill()` เป็นขั้นบันได — ทำให้ขอบเนียน

> spec งานก่อนหน้า (Fix A/B ลดต้นทุนการวาดบนมือถือ) ย้ายไปอยู่ที่ `docs/tasks/mobile-paint-perf.md`

## บริบท

ลาย `french` แบบขอบคม (`soft: false` ซึ่งเป็นค่า default) ใน editor 3D มีเส้นแบ่งสีเป็น
ขั้นบันไดชัดเจน แทนที่จะเป็นเส้นโค้งเรียบ (เห็นจากงาน "Classic Formal French" v2)

รูปทรงทุกแบบที่วาดผ่าน `fill()` เป็นแบบนี้หมด: french, swirl_tip, leaf, flower, butterfly,
star, heart, circle, tortoise, fruit — แต่เห็นชัดที่สุดในเส้นที่**เกือบแนวนอน**
อย่างเส้นยิ้มของ french

## สาเหตุ

`packages/patterns/src/geometry.ts:89` — `fill()` เติมรูปหลายเหลี่ยมด้วยเส้นแนวนอนเรียงกัน (scanline)

- ระยะห่างแถว `step = brushWidth × 0.45` → french ใช้ `brushWidth 0.025`
  แต่ละแถวห่างกัน 0.011 UV ≈ **11.5 px** บน texture 1024
- แต่ละแถวเป็นแถบหัวกลมที่**ขอบบน-ล่างตรง** ความยาวแถวคำนวณจากจุดตัดของขอบรูป
  ที่ v ของแถวนั้น**จุดเดียว**
- ขอบรูปที่เอียงน้อยจึงกลายเป็นแถบตรงยาวต่อกันเป็นช่วง ๆ แต่ละช่วงห่างกัน 11.5 px →
  ขั้นบันได ยิ่งขอบเกือบแนวนอน ขั้นยิ่งยาว
- `softness 0.05` ฟุ้งแค่ 5% ของรัศมีแต้ม (`drawDabs` ใช้ gradient จาก 0.95r ถึง r)
  ขอบจึงแทบคม ไม่มีอะไรกลบขั้น

ไม่ใช่ปัญหาของ rasterizer ฝั่ง web — `drawDabs` วาดแต้มกลม antialias ถูกต้องแล้ว
ปัญหาอยู่ที่ **ข้อมูล stroke** ที่ `fill()` สร้าง

## ทางเลือกที่พิจารณา

| ทาง | ข้อดี | ข้อเสีย | ตัดสิน |
|---|---|---|---|
| **A. ลากเส้นขอบรอบรูป** (ใน `fill()`) | แก้จุดเดียว ไม่แตะ schema/API/DB/web | รูปขยายออก ≤ ครึ่งแปรง | **เลือก** |
| B. stroke ชนิดใหม่ `polygon` วาดด้วย `ctx.fill(path)` | ขอบตรงเป๊ะ ข้อมูลเล็กลง | แตะ contracts, rasterizer, mirror, API, AI python, ลูกค้าเก่าเปิดงานใหม่ไม่ได้ | ไม่เลือกตอนนี้ — blast radius ใหญ่เกินกับอาการ |
| C. ลด `step` ให้ถี่ขึ้น | แก้ง่าย | ขั้นเล็กลงแต่ไม่หาย, stroke เพิ่ม 2–4 เท่า ชนเพดาน 500/เลเยอร์ | ไม่เลือก |
| D. เพิ่ม softness | แก้ง่าย | ขอบเบลอ ไม่ใช่ขอบคมที่ผู้ใช้สั่ง | ไม่เลือก |

## ทำไมทาง A ทำให้ขั้นหายจริง

แถว scanline แต่ละแถวยื่นเลยขอบรูปจริงได้ไม่เกินรัศมีแปรง `r = brushWidth / 2`
(ส่วนที่ยื่นคือมุมของขั้นบันได) และส่วนที่เว้าเข้าไปก็ไม่เกิน `r` เช่นกัน

เส้นขอบที่ลากทับตามแนวขอบรูปจริงด้วยแปรงกว้างเท่ากัน ครอบแถบ **ขอบรูป ± r**
ทั้งหมด จึงกลบทั้งมุมที่ยื่นและร่องที่เว้า ขอบที่มองเห็นกลายเป็นเส้น offset ของขอบรูป
ซึ่งเรียบตามรูปจริง

## การเปลี่ยนแปลง

ไฟล์เดียว: `packages/patterns/src/geometry.ts` ฟังก์ชัน `fill()`

1. หลังวนสร้างแถว scanline เสร็จ ให้ต่อท้ายด้วย stroke เส้นขอบ **1 เส้น**:
   - จุด: `[...poly, poly[0]]` (ปิดรูป)
   - `line(points, color, brushWidth, { opacity, softness })` — สี ความกว้าง ความฟุ้ง เท่ากับแถว
2. เพิ่มเส้นขอบ**เฉพาะเมื่อ `opacity >= 1`**
   - เหตุผล: แถวที่ทึบไม่เต็ม (เช่น tortoise `opacity 0.55`) ทับกันแล้วสีสะสม
     ถ้าเพิ่มเส้นขอบที่ทึบเท่ากันจะได้ขอบเข้มกว่าเนื้อในเป็นวงชัด
     กรณีนี้คงพฤติกรรมเดิม (ลายพวกนี้ softness สูงอยู่แล้ว ขั้นไม่เห็น)
3. เส้นขอบต้องอยู่**หลัง**แถวทั้งหมดในอาร์เรย์ (วาดทับ)
4. ถ้า `poly` มีน้อยกว่า 2 จุด ไม่ต้องเพิ่มเส้นขอบ
5. อัปเดตคอมเมนต์เหนือ `fill()` ให้บอกว่ามีเส้นขอบปิดท้าย และทำไม
   ลบประโยค "ขอบแนวนอนหดเข้าครึ่งความกว้างแปรง เพื่อให้ขอบรูปตรงกับรูปทรงที่สั่ง"
   ถ้าไม่จริงแล้ว — **ห้ามลบการหด `± radius` ของแถว** (ข้อ "ห้ามแตะ")

## ผลข้างเคียงที่ยอมรับ

- **รูปขยายออกราว `brushWidth / 2`** รอบทิศ (french 0.0125 UV, flower 0.004 UV)
  ขนาดนี้อยู่ในระดับเดียวกับที่แถว scanline ยื่นเลยขอบบน-ล่างอยู่แล้วในโค้ดปัจจุบัน
- **stroke เพิ่ม 1 เส้นต่อการเรียก `fill()`** — แย่สุดคือ tortoise เรียก 19 ครั้ง
  (ก้อนเข้ม 7 ก้อนทึบ 0.55 ไม่เพิ่ม, จุด 12 จุดทึบเต็มเพิ่ม 12) วัดได้ 279 stroke ต่อลาย
  ลายอื่นเพิ่มหลักหน่วย ไกลจากเพดาน 6 × 500
- **งานที่บันทึกไว้แล้วไม่เปลี่ยน** — stroke ถูกเก็บเป็นข้อมูลตอนบันทึก
  ต้อง apply recipe ใหม่ถึงจะได้ขอบเนียน (ไม่ทำ migration)

## Edge cases

| กรณี | ที่ต้องเป็น |
|---|---|
| รูปเว้า (หัวใจ, ดาวสี่แฉก) | เส้นขอบเดินตามจุดของรูปตรง ๆ ไม่ต้อง offset จึงไม่มีปัญหาเส้นตัดตัวเอง |
| รูปเล็กมากจนไม่มีแถวเลย (ลูปไม่เข้า) | ยังได้เส้นขอบ 1 เส้น → รูปไม่หายไปเฉย ๆ (ดีกว่าเดิม) |
| ขอบรูปทับขอบ texture (french มี `[1,0],[0,0]`) | จุดถูก clamp 0–1 ใน `line()` อยู่แล้ว ส่วนนอกเล็บถูกตัดทิ้งเอง |
| มือซ้าย | `mirrorStroke` กลับ x ของ brush stroke ทุกเส้น รวมเส้นขอบ — ไม่ต้องทำอะไรเพิ่ม |
| จำนวนจุดเส้นขอบ | circle 36, heart 48, sparkle 64, french ~23 — ต่ำกว่า `MAX_POINTS_PER_STROKE` 2000 มาก |
| `opacity` < 1 | ไม่มีเส้นขอบ = พฤติกรรมเดิมทุกประการ |

## Acceptance criteria

1. `fill()` ที่ `opacity` 1 คืน stroke เท่าเดิม + 1 โดยเส้นสุดท้ายเดินตาม `poly` และปิดรูป
2. `fill()` ที่ `opacity` < 1 คืน stroke เหมือนเดิมทุกประการ
3. เส้นขอบใช้สี ขนาด (`px(brushWidth)`) ความทึบ ความฟุ้ง เท่ากับแถว
4. preset ทุกตัวยังสร้างเอกสารที่ผ่าน schema และไม่เกิน 6 เลเยอร์
5. ลายเดิม seed เดิมได้ผลเดิมทุกครั้ง (determinism)
6. ตรวจด้วยตา: french ขอบคมใน `render_preview` / editor 3D ไม่มีขั้นบันได

## Tests

เพิ่มใน `packages/patterns/src/patterns.test.ts` (หรือไฟล์เทสใหม่ของ `geometry.ts`):

- **fill มีเส้นขอบปิดรูป**: `fill(circle(0.5, 0.5, 0.2), '#000000')` → stroke สุดท้ายมีจุดแรก = จุดสุดท้าย,
  จำนวนจุด = จำนวนจุดของรูป + 1, `size`/`softness`/`opacity` ตรงกับแถวก่อนหน้า
- **opacity < 1 ไม่มีเส้นขอบ**: เทียบกับการคำนวณแถวล้วน — ไม่มีเส้นที่มีจุดมากกว่า 2
- **รูปเล็กกว่าระยะแถว** ยังคืน stroke อย่างน้อย 1 เส้น
- **ขอบ french เรียบ (property test ไม่ผูก implementation)**: rasterize stroke ของ
  `renderPattern({ type: 'french', color: '#ffffff', smile: 0.08 })` ลงตาราง coverage แบบง่าย
  (จุดอยู่ในรัศมีแต้มใด ๆ หรือไม่) แล้ววัดขอบล่างของพื้นที่สีในแต่ละคอลัมน์ u —
  ความต่างระหว่างคอลัมน์ติดกันต้องไม่กระโดดเกิน ~2 px ที่ texture 1024
  (ปัจจุบันกระโดด ~11 px) **ถ้าเขียนแล้วเปราะหรือช้าเกิน 1 วินาที ให้ข้ามแล้วรายงานเหตุผล**
- เทสเดิมทั้งหมดต้องผ่าน

## Complexity

- เวลา: เพิ่ม O(จำนวนจุดของรูป) ต่อ `fill()` — เดิมเป็น O(แถว × จุด) อยู่แล้ว ไม่เปลี่ยนอันดับ
- ข้อมูล: +1 stroke และ +(จุดของรูป + 1) จุด ต่อ `fill()` ที่ทึบเต็ม
- ฝั่ง render: เพิ่มแต้มราว ความยาวเส้นรอบรูป ÷ (spacing × size) — french ≈ 2.2 UV ÷ (0.25 × 0.025)
  ≈ 350 แต้ม ต่อเล็บ วาดตอน replay เท่านั้น ไม่ใช่ทุกเฟรม
