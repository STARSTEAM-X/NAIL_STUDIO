## 2. สิ่งที่ตรวจพบ (หลักฐานจากโค้ด)

### A. ไอคอน — ใช้ 3 ระบบปนกันในหน้าเดียว

1. **`EditorToolRail.tsx:9-13`** ใช้ตัวอักษร Unicode ดิบ `☝ ✎ ✦ ✧` เป็นไอคอน
   ทั้งที่แอปมีชุด `<Icon>` SVG อยู่แล้ว — ตัวอักษรพวกนี้เรนเดอร์ด้วย emoji font
   ของ OS จึงหน้าตาต่างกันทุกเครื่อง ขนาด/น้ำหนักเส้นคุมไม่ได้ และ baseline ไม่ตรง
2. **`index.css:1031-1032`** undo/redo ใช้ `content: '↶' / '↷'` ผ่าน `::before`
   พร้อม `font-size: 0` ที่ตัวปุ่มเพื่อซ่อนข้อความ — ไอคอนที่เป็น CSS content
   ค้นหาไม่เจอ เปลี่ยนยาก และ `font-size: 0` เป็นรูปแบบที่เปราะ
3. **`<Icon>` ที่มีอยู่ก็ใช้ผิดความหมาย**
   - `PaintToolbar.tsx` : แปรง = `palette`, ยางลบ = `x` (x แปลว่า "ปิด/ยกเลิก")
   - `EditorSaveMenu.tsx` : ไฟล์ JSON = `layers`, แชร์ = `arrow-up-right`
     ทั้งที่ `Icon` มี `share` อยู่แล้ว
   - `NailEditor.tsx` : แท็บ "ประวัติ" = `remix` (ควรเป็น `clock`)
4. `DecorationPanel.tsx` แสดงของตกแต่งเป็น `.chip` ข้อความล้วน ไม่มีภาพตัวอย่าง —
   ผู้ใช้ต้องกดใส่แล้วลบทิ้งถึงจะรู้ว่าหน้าตาเป็นอย่างไร

### B. สี — token มีแล้วแต่หน้า editor ไม่ใช้

นับเฉพาะช่วง editor ใน `index.css` (บรรทัด 820–1420):

- **สี hex เขียนตรง 30 จุด / 20 ค่าไม่ซ้ำ** เช่น `#f7f1f2` (hover, 6 ครั้ง),
  `#2f2627` (5 ครั้ง), `#30201f`, `#211916`, `#17120f`, `#fcfafb`, `#eee6e7`,
  `#e9e3e4`, `#e8e0e1`, `#eee7e8`, `#e4dcdd` — เทาอมชมพู 5 เฉดที่แยกด้วยตาไม่ออก
- **font-size 19 ค่าไม่ซ้ำ** (0.55 / 0.62 / 0.63 / 0.65 / 0.68 / 0.7 / 0.72 /
  0.75 / 0.76 / 0.78 / 0.8 / 0.82 / 0.85 / 0.9 / 0.92 / 1 / 1.05 / 1.15 / 1.25 rem)
  ทั้งที่ `tokens.css` มี `--fs-xs … --fs-2xl` และคอมเมนต์ระบุชัดว่าตั้งสเกลไว้
  "เพื่อหยุดการเดาค่า" — หน้า editor ไม่ทำตามเลย
- **border-radius 7 ค่าไม่ซ้ำ** ทั้งที่มี `--r-xs … --r-full`
- **พื้นเข้ม 3 เฉดที่ไม่มีความสัมพันธ์กัน**: tool rail `#30201f`,
  editor-body `#211916`, viewport `#17120f` — ไม่ได้มาจากสเกลเดียว
- **สถานะ busy ใช้ `#d58a34`** แต่ token `--warn` คือ `#b25a0d` → สีเตือนมี 2 ค่าในแอปเดียว
- **`--muted: #7d6f66` บนพื้น `--surface`** ให้ contrast ≈ 4.3:1 ซึ่งต่ำกว่าเกณฑ์
  WCAG AA (4.5:1) และหน้านี้ใช้ `--muted` กับตัวอักษรขนาด 0.63–0.7rem หลายจุด
  (`.editor-topbar-project span`, `.editor-profile-trigger-copy small`,
  `.editor-topbar-status`) — เล็กและจางพร้อมกัน

### C. UX / โครงหน้าจอ

5. **`openPanel()` (`NailEditor.tsx:86-89`) มีผลข้างเคียงที่ผู้ใช้ไม่ได้สั่ง** —
   กดแท็บ "มือ" หรือ "AI" จะ `setMode('paint')` เงียบ ๆ ทำให้โหมดของตกแต่ง
   ที่กำลังทำอยู่หลุดไปโดยไม่มีอะไรบอก
6. **`DecorationPanel` คืน `null` เมื่อ `mode !== 'decorate'`** — เข้าแท็บ "ตกแต่ง"
   ในจังหวะที่ mode ไม่ตรงจะเห็นแค่หัวข้อกับพื้นว่าง ไม่มี empty state
7. **`LayerPanel` ถูกยัดท้าย `PaintToolbar`** — ต้องเลื่อนผ่านเครื่องมือ/สี/ขนาด/
   ผิวเล็บ/ทรง/ความยาว ทั้งหมดก่อนจะถึงเลเยอร์ ในคอลัมน์กว้าง 290px
8. **`LayerPanel` คลิกชื่อเลเยอร์ = เข้าโหมดเปลี่ยนชื่อทันที** (`beginRename`)
   ขัดความคาดหวังสากล (คลิก = เลือก, ดับเบิลคลิก = เปลี่ยนชื่อ)
9. **`.toolbar-paint .field output { margin-top: -1.25rem }`** — ดึงตัวเลขขึ้นไป
   ทับบรรทัด label ด้วย negative margin จะชนกันทันทีที่ label ยาวขึ้นหรือขึ้นบรรทัดใหม่
10. **สไลเดอร์ทุกตัวไม่มีช่องพิมพ์ตัวเลข** — ขนาดแปรง 8–400 บนรางกว้าง ~200px
    = 1px ของรางเท่ากับ ~2 หน่วย ตั้งค่าตรงเป๊ะไม่ได้
11. **`NailStrip` อยู่นอก `.editor-body` ล่างสุดของหน้า** — ตัวเลือกนิ้วซึ่งเป็น
    สิ่งที่กดบ่อยที่สุด อยู่ไกลจากทั้งแผงเครื่องมือและโมเดล 3 มิติ
12. **ไม่มีตัวควบคุมมุมมองที่ viewport** — zoom / reset ต้องไปกดปุ่ม "ดูทั้งมือ"
    ที่ซ่อนอยู่ในแถบล่างสุด
13. **คีย์ลัดมีแค่ 1–5 (เลือกนิ้ว) และ Ctrl+Z/Y** — ไม่มี B/E สลับแปรง-ยางลบ,
    ไม่มี `[` `]` ปรับขนาด, ไม่มีหน้าจอช่วยเหลือคีย์ลัด
14. **`.editor-topbar-feedback` จำกัด `max-width: 13rem` + `white-space: nowrap`**
    ข้อความ error ยาวถูกตัดด้วย ellipsis อ่านไม่จบ และถูก `display: none` ทิ้ง
    ทั้งก้อนที่ ≤900px → error หายไปเงียบ ๆ บนแท็บเล็ต
15. **`.editor-tool-rail-footer` เขียนคำว่า "TOOLS"** เป็นอังกฤษกลางหน้าจอภาษาไทย
    ไม่ได้ให้ข้อมูลอะไร

### D. การเข้าถึง (a11y)

16. **แถบเครื่องมือซ้ายกับแท็บขวาใช้ semantic คนละแบบ** ทั้งที่ทำงานเหมือนกัน —
    ซ้ายเป็น `<nav>` + `aria-pressed`, ขวาเป็น `role="tablist"` + `aria-selected`
17. **แท็บขวาไม่มี `aria-controls` / `role="tabpanel"`** และไม่รองรับปุ่มลูกศร
    ตาม WAI-ARIA tabs pattern
18. **tooltip ใช้ `title` อย่างเดียว** — ไม่ขึ้นบนอุปกรณ์สัมผัส และไม่ขึ้นตอน
    โฟกัสด้วยคีย์บอร์ด ปุ่มไอคอนล้วนหลายตัวจึงไม่มีคำอธิบายที่เข้าถึงได้จริง
19. **swatch สีมี `aria-label` เป็นค่า hex** (`สี #b5314c`) — screen reader อ่านว่า
    "สี ชาร์ป บี ห้า สาม หนึ่ง..." ควรตั้งชื่อสีเป็นคำ

## 3. แผนการแก้ (เรียงตามผลกระทบ)

### รอบที่ 1 — ระบบพื้นฐาน (สี + ไอคอน)

**1.1 เพิ่มไอคอนที่ขาดใน `Icon.tsx`**
`hand`, `brush`, `eraser`, `wand` (AI), `undo`, `redo`, `eye`, `eye-off`,
`copy`, `download`, `arrow-up`, `arrow-down`, `zoom-in`, `zoom-out`, `keyboard`

**1.2 แทนไอคอนทุกตัวในหน้า editor ด้วย `<Icon>`**

| tool rail — AI | `✧` | `<Icon name="wand">` |

```css

--editor-chrome-line: var(--rule);

--editor-shell-900:   #17120f;   /* viewport */
--editor-shell-800:   #211916;   /* editor-body */
```

- `--editor-save-dot-busy` ใช้ `--warn` แทน `#d58a34`
- แก้ `--muted` เป็น `#6d5f56` (contrast ≈ 5.6:1 ผ่าน AA) — กระทบทั้งแอปในทางที่ดีขึ้น

**1.4 บังคับใช้สเกล token**
แทน font-size ทั้ง 19 ค่า → `--fs-xs … --fs-2xl`
แทน border-radius ทั้ง 7 ค่า → `--r-xs … --r-full`

### รอบที่ 2 — โครงหน้าจอและการใช้งาน

**2.1 `openPanel` ไม่แตะ mode เอง** — ผูก mode กับแท็บแบบตรงไปตรงมา
(`decorate` ↔ mode decorate, แท็บอื่นคงโหมดวาด) และไม่รีเซ็ตโหมดตอนสลับไป
แท็บมือ/AI

**2.2 `DecorationPanel` มี empty state** — เมื่อ mode ไม่ตรง แสดงปุ่ม
"เข้าสู่โหมดตกแต่ง" แทนพื้นว่าง

**2.3 แยก `LayerPanel` ออกจาก `PaintToolbar`**
ย้ายไปเป็นแท็บที่สามของแผงขวา (`แคนวาส | เลเยอร์ | ประวัติ`) — ตรงกับที่
Photoshop/Figma วางไว้ และปลดคอลัมน์ซ้ายให้เหลือแค่เครื่องมือ

**2.4 `LayerPanel` เปลี่ยน interaction** — คลิก = เลือกเลเยอร์,
ดับเบิลคลิก / ปุ่มดินสอ = เปลี่ยนชื่อ; ปุ่มขึ้น/ลง/ลบเป็นไอคอนแถวเดียว

**2.5 ทุกสไลเดอร์มีช่องตัวเลข** — เปลี่ยน `<output>` เป็น
`<input type="number">` ที่ผูกค่าเดียวกัน และลบ `margin-top: -1.25rem` ทิ้ง
(ใช้ grid `label / value` แทน)

**2.6 ย้าย `NailStrip` เข้าไปใต้ viewport** (ในกล่อง `.editor-body`)
ให้ตัวเลือกนิ้วอยู่ติดกับสิ่งที่มันควบคุม

**2.7 เพิ่มแถบควบคุมมุมมองมุมล่างขวาของ viewport** —
ซูมเข้า / ซูมออก / ดูทั้งมือ เป็นปุ่มไอคอนลอย

**2.8 เพิ่มคีย์ลัดเครื่องมือ + หน้าช่วยเหลือ**
`B` แปรง · `E` ยางลบ · `[` `]` ลดเพิ่มขนาด · `?` เปิดตารางคีย์ลัด
(ใช้ตัวกรอง `isEditableTarget` เดิมจาก `fingerShortcuts.ts` ซ้ำได้)

**2.9 error ใน topbar ไม่ถูกตัดทิ้ง** — ย้ายข้อความ error ที่ยาวไปแสดงเป็น
`.editor-notice` (แถบเต็มความกว้าง มีอยู่แล้ว) แทน `nowrap` + `display: none`

**2.10 ลบ footer "TOOLS"** ในแถบเครื่องมือซ้าย

### รอบที่ 3 — การเข้าถึง

**3.1 tool rail ใช้ `role="tablist"` / `role="tab"` + `aria-controls`**
ให้เหมือนแผงขวา และรองรับปุ่มลูกศรตาม WAI-ARIA
**3.2 ครอบ inspector ด้วย `role="tabpanel"` + `aria-labelledby`**
**3.3 ปุ่มไอคอนล้วนใช้ tooltip component ที่ขึ้นตอน focus** ไม่ใช่ `title` เปล่า
**3.4 ตั้งชื่อสีเป็นคำ** ใน `SWATCHES` (แดงเลือดหมู, แดงเข้ม, เนื้อ, ชมพูอ่อน,
เทาเขียว, ขาว, ดำ, ทอง) แล้วใช้ใน `aria-label` + tooltip

## 4. เกณฑ์ผ่าน (Acceptance Criteria)

- [ ] ไม่มี Unicode glyph หรือ CSS `content:` ที่ทำหน้าที่ไอคอนเหลืออยู่ในหน้า editor

  (ยกเว้นค่าที่นิยามใน `tokens.css`)

- [ ] ทุกคู่สีข้อความ/พื้นในหน้า editor ผ่าน WCAG AA (4.5:1 สำหรับ text ปกติ)
- [ ] สลับแท็บเครื่องมือแล้วโหมดของตกแต่งไม่หลุดเอง
- [ ] แผงเลเยอร์เข้าถึงได้โดยไม่ต้อง scroll ผ่านแผงวาด
- [ ] ทุกสไลเดอร์พิมพ์ค่าเป็นตัวเลขได้ และค่าไม่ทับ label
- [ ] คีย์ลัด B / E / [ / ] / ? ทำงาน และไม่ยิงตอนโฟกัสอยู่ในช่องกรอก
- [ ] แถบเลือกนิ้วอยู่ติดกับ viewport ในทุก breakpoint
- [ ] `npm run typecheck` และ `npm run test` ผ่าน

## 5. กรณีขอบ

- คีย์ลัดใหม่ต้องไม่ยิงตอนโฟกัสอยู่ใน input/textarea/select/contenteditable
  (ใช้ `isEditableTarget` เดิม)
- `?` บนแป้นพิมพ์ไทยคือ Shift+`/` — ต้องเช็ค `event.code` ด้วย ไม่ใช่ `event.key` อย่างเดียว
- ช่องตัวเลขต้อง clamp ค่าที่พิมพ์เกินขอบเขต ไม่ส่งค่านอกช่วงเข้า store
- ย้าย `NailStrip` เข้า `.editor-body` แล้วต้องไม่ทำให้ `min-width: 0`
  ของ viewport เสีย (คอมเมนต์ `index.css:601` อธิบายไว้ว่าทำไมมันสำคัญ)
- แยก `LayerPanel` ออกมาแล้ว state `activeLayerId` ต้องยังผูกกับเล็บที่เลือกอยู่
- เปลี่ยน `--muted` กระทบทุกหน้า → ต้องดูหน้า community / appointments / shops ด้วย
- ที่ ≤720px แถบควบคุมมุมมองต้องไม่ทับแถบเลือกนิ้ว

## 7. ความซับซ้อน

ทั้งหมดเป็นงาน presentation layer — ไม่มีการเปลี่ยน algorithm, schema หรือ API
ความเสี่ยงหลักคือ regression ทางสายตาจากการเปลี่ยน `--muted` ซึ่งกระทบทั้งแอป

## จุดที่ต่างจากสเปก

1. **`color: #fff` ยังเหลือ 7 จุด** — เป็นสีตัวอักษร/เส้นขอบสีขาวบนพื้นสีเข้มหรือ
   พื้น accent ซึ่งเป็นค่าสัมบูรณ์ ไม่ใช่การเลือกธีม และเขียนแบบเดียวกับที่เหลือทั้งแอป
   ส่วนที่เป็น *พื้นผิว* แปลงเป็น `--editor-chrome` ครบแล้ว
2. **เพิ่ม `--fs-2xs: 0.65rem` เข้าสเกล** — สเกลเดิมเริ่มที่ 0.72rem แต่โครมของ
   editor (แถบบนสูง 58px) มีข้อความ 0.62–0.68rem หลายจุด การดันขึ้น 0.72rem
   ทั้งหมดจะทำให้แถบบนล้น
3. **`--muted` ได้ 6.04:1 บน `--surface` ไม่ใช่ 5.6:1 ตามที่ประเมินไว้ในสเปก**
   และค่าเดิม `#7d6f66` วัดได้ 4.77:1 บน `--surface` (ผ่าน) แต่ 4.41:1 บน
   `--ground` (ไม่ผ่าน) — ตัวเลข 4.3:1 ในหัวข้อ B ของสเปกคลาดเคลื่อน ข้อสรุปเดิม
   (ต้องแก้) ยังถูก เพราะจุดที่ไม่ผ่านคือบน `--ground`
4. **แก้บั๊กแถมที่เจอระหว่างทำ** — `.editor-notice` ทุกใบเป็น `position: fixed;
   inset: 0 0 auto` ของตัวเอง เมื่อมีสองเรื่องพร้อมกัน (งานสำรอง + บันทึกล้มเหลว)
   แถบหลังทับแถบแรกจนอ่านไม่ได้ ย้ายตัว fixed ไปที่ `.editor-notices` ที่ครอบแทน
5. **แก้บั๊กแถมข้อสอง** — `NailFocus` ไม่ล้าง `goal.current` เมื่อ `focus` กลายเป็น
   null ทำให้ปุ่มซูมใหม่กับการจ่อเล็บที่ค้างอยู่ลากกล้องคนละทางพร้อมกัน
