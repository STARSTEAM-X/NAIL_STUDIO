## 3 · ข้อสรุป

### 3.1 · D-22 ยืนยันแล้ว และหนักแน่นกว่าที่คาด

**Recipe ดีกว่า Document 5.5 เท่าในอัตราผ่าน (73.3% เทียบ 13.3%) และ 30 เท่าในความเร็ว (6.3 s เทียบ 187 s)**

เงื่อนไข B ผ่านรอบแรก **0 จาก 15** — ไม่มีสักครั้งเดียวที่โมเดลสร้าง DesignDocument
ที่ถูกต้องได้ในรอบแรก และ p95 ที่ **461 วินาที** ทำให้ใช้งานจริงไม่ได้โดยสิ้นเชิง
ต่อให้อัตราผ่านจะดีกว่านี้ก็ตาม

→ **แนวทางของซอร์สเดิม (`AI_JSON_Generation`) ที่ให้ LLM สร้างดีไซน์เต็มรูป ใช้ไม่ได้จริง**
ยืนยันการตัดสินใจ D-22 ด้วยตัวเลข ไม่ใช่ด้วยเหตุผลอย่างเดียว

### 3.2 · `format: "json"` ไม่ช่วยอะไรเลย — ขัดกับที่ผมเขียนไว้ใน A-17

เงื่อนไข A กับ C ได้ผล**เท่ากันเป๊ะ** (53.3% / 73.3% / ซ่อมเฉลี่ย 0.73)

`algorithms.md` A-17 เขียนว่า JSON mode เป็น "ชั้นป้องกันที่ 1 ทำให้ผลลัพธ์เป็น JSON
ที่ parse ได้เสมอ" — **วัดแล้วไม่จริงสำหรับกรณีนี้** เพราะ JSON parse ผ่าน 100%
ทุกเงื่อนไขอยู่แล้วแม้ไม่เปิด JSON mode ปัญหาทั้งหมดอยู่ที่ **ระดับ schema ไม่ใช่ระดับ syntax**

→ ต้องแก้ A-17: JSON mode ไม่ใช่ชั้นป้องกันที่มีผลจริง ชั้นที่ทำงานจริงคือ
**schema validation + referential integrity**

### 3.3 · โมเดลไทยชนะ

typhoon2-8b 73.3% เทียบ qwen2.5:7b 60% → การเลือกโมเดลของซอร์สเดิมถูกต้อง
และผลไม่ได้ขึ้นกับโมเดลอย่างเดียว เพราะ Recipe ชนะ Document ในโมเดลเดียวกัน

## 4 · สาเหตุความล้มเหลวทั้งหมดเป็นเรื่องเดียวกัน

ทุกเคสที่ไม่ผ่านในเงื่อนไข A/C/D ล้มด้วยข้อความเดียวกัน:

```
accentNails: Invalid input: expected array, received undefined
decorations: Invalid input: expected array, received undefined
```

**โมเดลละฟิลด์ที่ควรเป็น array ว่างทิ้ง แทนที่จะใส่ `[]`** และซ่อมอีก 2 รอบก็ยังละอยู่

สาเหตุคือ **prompt ที่ผมเขียนเอง** — schema text ระบุว่า `"array (0-4) ของ ..."`
ซึ่งโมเดลตีความว่า "ถ้าไม่มีของ ก็ไม่ต้องใส่ฟิลด์" **ไม่ใช่ข้อจำกัดของโมเดล**

## 5 · สถานะเทียบเกณฑ์ที่ตั้งไว้ล่วงหน้า

`algorithms.md` A-17 ตั้งเกณฑ์ไว้ก่อนทดลองว่า:

> ถ้าอัตราผ่านหลัง repair < 85% ให้เปลี่ยนไปใช้ทางเลือก (จ)

**ปัจจุบัน 73.3% ซึ่งต่ำกว่าเกณฑ์**

แต่ **ยังไม่ควรถอยไปทางเลือก (จ)** เพราะสาเหตุความล้มเหลวถูกระบุได้ชัดเจนและแก้ได้
ต้องแก้ prompt แล้ววัดใหม่ก่อนจึงจะตัดสินตามเกณฑ์ได้อย่างเป็นธรรม

### งานที่ค้างไว้ (Slice 6)

1. แก้ prompt: เพิ่มกฎ **"ทุกฟิลด์ต้องมีเสมอ ถ้าไม่มีของให้ใส่ `[]`"** + ใส่ตัวอย่าง output ที่มี array ว่าง
2. ทางเลือก: ใส่ `.default([])` ใน Zod ให้ validator ยอมรับการละฟิลด์ (ผ่อนปรน)
   — แต่ควรแก้ที่ prompt ก่อน เพราะการผ่อนปรน schema ซ่อนปัญหาไว้
3. รันซ้ำด้วยชุดทดสอบเดิม → **วัดว่าการปรับ prompt ช่วยได้กี่เปอร์เซ็นต์**
4. ถ้ายังต่ำกว่า 85% จึงพิจารณาทางเลือก (จ) ตามเกณฑ์
5. ขยายชุดทดสอบเป็น 100 รายการตามที่ A-17 กำหนด (spike นี้ใช้ 15 เพื่อความเร็ว)
